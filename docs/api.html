ChillLog API

The REST API behind ChillLog, the fridge-temperature monitor for Squanchy Bakery. Every example below is a real request and response, captured from the app running on the demo data (npm run seed, then this week's files uploaded). Long lists are trimmed.

Conventions

  • Base URL: http://127.0.0.1:3000/api after npm start. In npm run dev, the Vite dev server forwards /api to the same server.
  • JSON in, JSON out, except uploads (multipart/form-data) and the CSV export.
  • Times in responses are UTC, ISO 8601, in fields ending in Utc (2026-09-27T20:45:00Z). The app shows them in Israel time.
  • Dates you send are Israel time: 2026-09-17 or 2026-09-17T10:00, the way a date picker gives them. A date alone means the start of that day, except to in a range, which includes the whole day.
  • Temperatures are °C. °F logger files are converted when they come in.
  • No login. The app runs locally for one user; the server listens on 127.0.0.1 unless HOST is set.
  • The rules behind the numbers (above 5°C, door openings, gaps, warming) are in NOTES.md, "Detection parameters".

Errors

Every error is JSON with a sentence that can be shown to the user as-is. Conflicts with stored data add a machine-readable code: 

{
  "error": "A branch called \"Haifa\" already exists.",
  "code": "duplicate"
}
Status When
400 Invalid input. Form errors add issues, one per field: { "path": "name", "message": "Enter a name." }. Also bad JSON, a date that doesn't exist, a range that ends before it starts, too many files.
404 The branch, fridge, logger, upload or route doesn't exist.
409 Conflicts with what's stored: duplicate, invalid_move, already_processed.
413 An uploaded file is over 5 MB. Nothing from that request is kept.
500 A server fault. The response says only "Something went wrong on the server. Please try again."; the details go to the server log.

Uploads

Single and bulk upload are one pipeline. Each file is stored unchanged (named by its SHA-256), its logger is found from a line inside the file (Logger ID: TL-0231) or its name (TL-0417_2026-09-21.csv), and its readings are added in its own transaction, so one bad file never stops the rest. Uploading the same file again is always safe.

POST/api/uploadsUpload one or many logger files, get a report per file

multipart/form-data with one or more files in the files field. Limits: 5 MB per file, 50 files per upload, .csv / .txt / .tsv.

File status Meaning (reason)
processed Readings added.
already_uploaded Same file as before (same bytes). Nothing added.
needs_logger Stored, waiting for Summer to say which logger it is from: no_logger_id (none found) or unknown_logger (an ID that isn't registered; loggerCode says which).
failed Held back: stored, nothing added until fixed. looks_fahrenheit / looks_celsius (values look like the other unit), no_readings, or error.
rejected not_csv: wrong file type. Not stored.
Report field Meaning
readings.added New readings stored by this upload.
readings.alreadyStored Readings that were already in (overlapping files).
readings.err ERR readings: kept as a reading with no temperature.
readings.unreadable Rows that couldn't be read. Counted, never guessed.
readings.duplicatesInFile Rows repeated inside the file.
readings.beforePlacement Readings from before the logger was placed in any fridge.
range First and last reading in the file.
notes out_of_order (rows weren't in time order), date_format_differs (the file's day/month order isn't the logger's setting).

Overview

GET/api/overviewEvery fridge's status for one week, worst first

"This week" is the last full Monday–Sunday week in Israel time, because files arrive on Monday for the week before. ?week=2026-09-14 (any day in a week) shows another week.

status When (worst first)
alert Time above 5°C in the week (2+ readings in a row). alert has count, peak, total minutes.
warming Median of the last 24 h ≥ 0.5°C above the 24 h before, at the last reading.
gap More than 1 hour with no valid reading, including a file that stops early. gap has count and total minutes.
no_file No readings this week. noLogger: true if the fridge never had a logger.
ok None of the above. latest is the last reading.

sparkline is the week in 3-hour buckets, each with its minimum and maximum, so a single high reading still shows.

Fridge page

GET/api/fridges/:id?from=&to=One fridge over a range: chart data, time above 5°C, gaps
Query Notes
from, to Israel dates or date-times. to=2026-09-27 includes that whole day. Default: the last 7 days up to now. At most 366 days.

series.points holds at most 300 buckets with the minimum and maximum of each (never an average, which would hide a spike). Bucket size grows with the range: 15 min for a day, 1 h for a week, 3 h for 30 days. A bucket with no reading has null values, so the chart line breaks there. placements says which logger was in the fridge when; weekStatus is this fridge's entry from the overview.

GET/api/inspector/export?branchId=&fridgeId=&from=&to=The same list as a CSV download for Excel

Same query as /api/inspector. Times are in Israel time so Excel shows them as the files did. The file starts with a UTF-8 byte-order mark (so Excel reads °C and Hebrew names correctly) and uses CRLF line ends.
